# dw-agent LLM 后端

dw-agent 基于 Pi，为 3D 数字人提供拟人对话、独立 Agent 任务、角色档案和长期记忆。HTTP `/api` 接收业务操作；WebSocket `/dw-agent/v1` 负责鉴权、订阅和事件补收。

本次重写保留 v1 路径，但替换旧协议，不提供旧 WebSocket 业务命令兼容层。数字人尚未接入时应直接使用新契约。完整接口见 [协议规范](docs/protocol-v1.md)、[OpenAPI](schemas/openapi.json) 和 [WebSocket JSON Schema](schemas/protocol-v1.schema.json)。

## 运行

要求 Node.js 22.19+。在仓库根目录执行：

```powershell
npm ci --ignore-scripts
npm run hydrate:model-data
$env:DW_PROVIDER = "openai"
$env:DW_MODEL = "gpt-4.1-mini"
$env:OPENAI_API_KEY = "<your-key>"
npm run start:dw
```

Linux/macOS 可设置同名环境变量后运行 `npm run start:dw`。模型目录准备会获取 JSON 元数据，不调用推理接口；服务直接运行源码，不需要构建前端或全部上游包。尚无模型凭据时也可启动，随后在 WebUI 配置。

默认打开 `http://127.0.0.1:17850/`。首次生成的 bootstrap 令牌位于 `~/.dw-agent/access-token`，控制台仅显示路径。

| 环境变量 | 默认值 / 用途 |
|---|---|
| `DW_DATA_DIR` | `~/.dw-agent`，执行器数据 |
| `DW_PI_AGENT_DIR` | `<data-dir>/pi`，Pi 凭据、模型及全局资源配置 |
| `DW_PROVIDER`、`DW_MODEL` | 初始物理模型；需同时设置，已有保存配置优先 |
| `DW_TOKEN` | 覆盖文件中的 bootstrap 令牌，至少 16 个字符 |
| `DW_HOST`、`DW_PORT` | `127.0.0.1`、`17850` |
| `DW_ALLOWED_ORIGINS` | 附加浏览器 Origin 白名单；默认支持本机同端口 WebUI |

同一数据目录只能运行一个进程。锁由 proper-lockfile 维护；异常退出后等待锁过期，不要删除仍被运行进程持有的锁。远程部署应在可信网络或 HTTPS/WSS 反向代理之后运行，不要直接公开 bootstrap 令牌。

## 数字人接入流程

1. 使用 Bearer 令牌查询 `/api/bootstrap` 和 `/api/capabilities`，读取权限、默认资源和实际隔离能力。
2. `POST /api/sessions` 创建会话，选择人格、用户范围、工作区、执行配置和模型配置。客户端传注册资源 ID，不传任意 `cwd`。
3. WebSocket 发送 `hello`，随后订阅 `session:<id>`，携带上次确认处理的 `after_seq`。
4. `POST /api/sessions/:id/messages` 发起前台回复；需要工具执行时，单独 `POST /api/sessions/:id/tasks`。长任务不占用前台聊天的执行上下文。
5. 消费 `reply.segment`，依据 `message_id`、`segment_id` 去重；其他资源变化事件通过 ID 和修订号关联 HTTP 快照。
6. 根据应用需要提交场景上下文和表现反馈。场景只是有有效期的外部上下文，不成为系统指令；反馈记录客户端实际播放结果，不等于工具完成证明。

[Godot 4 示例](examples/godot/dw_agent_client.gd) 提供 HTTP 操作、事件订阅、持久化游标、幂等重试、任务控制和场景/表现接口。不包含 TTS、动作动画、VRM 重定向或渲染实现。

### 回复格式

每个可交付句段同时包含：

```json
{
  "message_id": "server-message-id",
  "segment_id": "server-segment-id",
  "index": 0,
  "expression": { "description": "轻轻点头", "language": "zh-CN" },
  "speech": "你好，我们开始吧。",
  "text": "（轻轻点头）你好，我们开始吧。",
  "task_refs": []
}
```

- `text` 是完整展示文本，始终以全角括号中的动作描述开头。
- `speech` 是不含动作描述的台词，可交给 TTS。
- `expression` 是自然语言表现描述，不是可执行脚本或绑定某个动画引擎的命令。
- `task_refs` 由服务端绑定，模型不能伪造已执行任务。

模型使用严格的 expression/speech 标记格式；只有完整闭合、校验通过的句段才会交付。格式错误不会通过第二次模型调用修复，也不会编造默认动作。已交付的部分句段在失败或取消后仍可查询。旧 `<actions>` 输出不是新协议的一部分。

## HTTP、事件与权限

HTTP 使用 `Authorization: Bearer <token>`；WebSocket 令牌只放在 `hello` 中。URL 不接受令牌。JSON 写操作使用 `Content-Type: application/json`，无参数的 POST 也发送 `{}`。

| 约定 | 行为 |
|---|---|
| 创建 / 动作 POST | 必须带 `Idempotency-Key`，重试使用相同方法、地址和请求体 |
| 资源响应 | `{id, revision, created_at, updated_at, data}` |
| 列表 | `{items, next_cursor}`；游标绑定原查询条件 |
| PATCH / DELETE | 使用 `expected_revision`；DELETE 放在查询参数中 |
| 错误 | `{error:{code,message,retryable,details?},request_id}`；响应头提供 `X-Request-Id` |
| 事件 | 独立 `event_id`、`stream_id`、递增 `seq`、类型、时间和资源关联 ID |
| 并发客户端 | 没有会话连接所有者；各订阅者独立补收、去重和授权 |
| 断开网络 | 不隐式取消已接受的回复、Agent 或后台 Job |

幂等记录保存资源引用，而不是记忆、日记或回复正文的副本。同一键返回同一资源的**当前**快照，不重复执行；资源已删除时返回不存在，不恢复旧正文。进程在结果确认前中断时，返回明确的中断状态和已记录资源引用，不自动重放未知结果的副作用。令牌密文只返回一次，重复发行请求不会再次泄露它。

`read`、`chat`、`execute`、`approve`、`manage` 是独立权限。托管令牌可限定会话和人格 × 用户范围并设置到期时间；`null` 表示不限范围，空数组表示没有该范围的访问权。撤销或到期后停止事件交付。**只有 bootstrap principal 可以发行、列出和撤销令牌**，普通 `manage` 权限不能扩大自己的权限。

流可为 `session:<id>`、`companion:<persona>:<user>` 或仅管理者可订阅的 `system`。客户端仅在处理成功后推进游标。删除后的历史或过期游标返回 `CURSOR_EXPIRED` 时，重新读取权威资源快照，再从允许的边界订阅；资源 404 表示已删除，不应自动重建。

## WebUI 与配置分工

WebUI 随服务提供。静态文件在启动时读取，修改后需重启服务并刷新浏览器。

- 工作台：创建、搜索、重命名和删除会话；分别提交对话和 Agent 任务；查看工具、审批、动作和使用量。
- 角色档案 `/personas`：系统提示、身份、表达、固定作息、重要日期、目标及角色扮演开关。
- 记忆与关系 `/companion`：当前人格 × 用户的关系、记忆审核、纠正、遗忘和召回预览。
- 生活任务 `/life`：计划、日记、细化、虚构状态、周期、上下文注入和独立调度注册。
- 模型与分工 `/models`：供应商、模型定义和能力、思考等级、模型配置中的 chat/agent/life 分工，以及实际模型可用性测试。
- 管理 `/admin`：注册工作区、执行配置、审批策略、托管令牌、MCP 和已安装扩展/技能。

重复条目使用表单编辑，不要求手写 JSON。角色目录在桌面使用窄列，编辑区占据剩余宽度；窄屏改为上下布局。不同范围和页面的非敏感草稿保留，API Key、OAuth 密钥和一次性令牌离页清空。

### 模型与实际预算

模型配置分别保存 `chat`、`agent`、`life` 角色的物理模型、思考等级和 `max_output_tokens`。查询同时返回声明、配置和有效预算；真实 provider 请求使用有效预算。没有 65536 的固定输出上限，但仍受模型声明和上下文窗口限制。

自定义模型的 Base URL 是 API 前缀，例如 `http://127.0.0.1:8000/v1`。模型名称可以含 `/`，URL 路径中需编码。配置保留原有兼容选项；API Key 作为字面量保存在 Pi 凭据存储，不返回客户端。能力声明不会赋予模型本身不支持的图像或推理能力，当前外部输入仍为文本。

模型测试创建独立 Job，显式执行一次短文本请求，显示实际耗时和 token。它会消耗推理额度，不测试工具或图像能力，不修改模型选择，不自动重试。临时 API Key 只用于本次测试，不写入 Job 输入或幂等结果。离开页面不取消测试；取消须显式操作。

Agent 任务保存执行时的模型、预算、工作区和策略快照。配置变化不会偷偷改变已接受任务的权限；恢复也沿用该任务的绑定。已有后台生活按项指定的模型保留，未单独指定时使用 life 分工。

## Agent、工作区与审批

前台对话不加载工具，不解析扩展命令或斜杠技能；Agent 使用独立的 Pi 原生工具循环、历史与检查点。任务可暂停、恢复、取消，工具调用和审批作为可查询资源。取消请求不伪装成已完成取消；已经产生的文件或外部副作用不会被自动撤销。

默认执行配置只允许受路径检查的文件工具，写操作需要审批。工作区是注册过的真实目录；受限工具拒绝越界路径、符号链接和执行器自身的数据/凭据目录。项目目录中的配置不会自动成为可信代码。

**工作目录和路径检查不是操作系统沙箱。** 当前能力接口明确报告没有进程沙箱。任意 shell、PowerShell、codemode、MCP 或第三方扩展执行必须选择明确的 `trusted_host` 策略并逐次审批。该模式运行在主机权限下，不能承诺隔离任意代码或其他本机进程。

审批绑定任务、工具调用、最终参数摘要和执行范围，不能换参数复用；拒绝、到期、取消或重启后不能沿用旧授权。最终检查位于扩展参数变更之后，并覆盖嵌套工具路径。

已安装扩展和技能只能在管理接口中发现、授权和重载，不提供任意远程代码安装接口。MCP 使用 Pi 原生配置、传输、工具发现和 OAuth 流程；状态、失败和工具目录来自真实连接。重载或连接配置变化需要执行器处于允许变更的状态。MCP 登出只删除本地凭据；上游不支持远端撤销时明确返回 `remote_revocation_supported:false`。

## 人格、记忆和生活

人格保存在 `<data-dir>/personas`，可参考 [人格示例](examples/personas/default.json)。没有文件时提供内置 `default`。ID 为 1–100 个字母、数字、下划线或短横线；系统提示最多 65536 字符。HTTP 使用数值修订号，由服务映射到原生人格文件版本。

会话固定创建时的人格快照；后台生活读取最新保存的角色卡。人格 ID × 用户 ID 是跨会话的共享记忆范围，用户 ID 不是认证凭据。启用角色扮演后创建新会话才使用新角色卡；不回扫旧对话提炼记忆。

### 记忆闭环

成功完成的交谈保存带说话者、时间和来源的脱敏摘录。主回复末尾可附带独立 `<companion>` 控制块，提出事实、事件、承诺、反思和有证据的关系变化；该块不进入台词，也不额外调用模型。模型提议先进入待审核状态，不能当作已确认事实直接召回。

检索使用本机 SQLite FTS5、Unicode 分词和中文二元词组，结合时间、重要性、持久性、强化和近重复抑制；这是词法检索，不是向量语义检索，没有隐式 embedding、重排或摘要调用。固定核心最多 8 条，动态召回最多 6 条。管理页预览不增加强化次数。

亲密分为 −100～100，模型单轮最多变化 ±3，每当地日绝对变化最多 12，必须附当前用户原文证据。情绪与唤醒值按 4 小时半衰期回落；长时间无互动时亲密分向 0 冷却。稳定系统提示和角色卡不能被模型改写。

归档可恢复；遗忘清除记忆正文、引用、关联来源与索引，并保留不含正文的防重放标记。它不会改写当前原生上下文或外部备份。记忆来源被遗忘时，依赖它的日记和衍生素材也会失效；Job 结果仅保留资料引用，不另存日记正文。

### 虚构生活与日记

自动任务需明确注册人格 × 用户调度范围。注册、停用和移除是独立持久化操作，不依赖浏览器在线；自动和手动日程、日记、细化均进入可查询、可取消的 Job。自动维护只处理当前当地日期，不补造停机期间的过去日记。

| 配置 | 默认 |
|---|---|
| 日程 | 开启，07:30，10 条 |
| 日记 | 开启，23:10 |
| 日记形式 / 篇幅 / 写实程度 | auto / standard / balanced |
| 日记保留 | 最近 14 篇，可设为 1–60 |
| 拟人化状态 / 强度 | 开启，50 / 100 |
| 健康、胃口、基础周期 | 开启，可分别关闭 |
| 被动状态注入 | 开启 |
| 日程细化 | 默认关闭；启用后提前 3 分钟 |
| 六阶段周期 | 默认关闭；阶段 5 / 5 / 3 / 1 / 8 / 6 天 |
| 手动状态持续时间 | 默认 12 小时，可设为 1–72 小时 |

状态、天气、地点与计划是虚构角色投影，不声称观察到现实。计划不会随时间流逝自动成为已发生事件；细化标为 simulated。日记区分交谈/手工证据、计划、模拟和状态，不能把角色台词当作现实任务完成证明。

日程、日记正文、修订、衍生素材及细化保留原有有界请求预算和质量处理。短 JSON 任务默认关闭思考或使用模型支持的最低等级；真实请求数、token、失败、取消和降级警告可查询。确定性备用内容明确标注来源，不冒充模型生成成功。

设计参考 [memory_companion](https://github.com/menglimi/astrbot_plugin_memory_companion) 和 [private_companion](https://github.com/menglimi/astrbot_plugin_private_companion)，采用独立 TypeScript 实现。不移植社交平台适配、群聊逻辑、主动消息或回复触发策略。

## 数据、删除与升级

- `api.sqlite`：公共资源、事件游标、幂等记录、权限元数据和执行绑定。
- `api-sessions`、`tasks`：独立的前台与任务原生日志、检查点；`sessions` 保留旧日志迁移入口。
- `companion.sqlite`：记忆、来源、关系与索引。
- `companion-life.sqlite`：生活状态、计划、日记和原生生成记录。
- Pi 的模型、MCP 和凭据文件仍使用原生格式。

升级在导入旧日志前创建备份，保存迁移标记；未知或损坏格式报错，不静默重置为空。旧 Agent 会话与前台上下文分离，未确认结果的模型/工具调用不会在重启后自动重放。原始迁移备份不会作为新会话重新导入。

迁移保留旧任务的真实工作区。如果旧目录已经不可用，或位于现在禁止访问的执行器数据/凭据目录中，历史仍可读，但任务标记 `WORKSPACE_UNAVAILABLE` 并拒绝恢复；不会改到另一个目录执行。需要在允许的工作区中明确创建替代任务。原始 `.api-backup` 文件保留用于恢复，属于需要另行管理的备份数据。

删除会话需要当前修订号，并拒绝仍在活动执行的会话。删除会清除该会话的公共正文、事件负载、原生日志、任务和检查点，保留最小删除标记和流序号，供其他客户端停止显示。它不撤销已执行工具的副作用，也不删除工作区文件、共享人格/记忆/关系/日记或已经注册的生活调度。

**删除和遗忘不是磁盘安全擦除。** 迁移备份、SQLite 底层文件历史和外部备份可能仍含旧数据。备份与人工清理应在服务停止后进行，并同时处理执行器目录及需要保留的原生配置；不要将密钥或敏感原文视为适合长期保存的内容。
